# ADR 0008: GCP service choices for Peach (Lab 9)

Date: 2026-11-17
Status: Accepted (code and Terraform written; not applied. Lab 9 alternative path: no GCP account, so nothing ran on Google Cloud. See docs/lab9-submission.md)

## Context

Peach runs on AWS: a static Next.js export on S3 + CloudFront, a FastAPI API on
Lambda (function URL, Mangum adapter), Postgres on Aurora Serverless v2 (0–1 ACU,
pauses), Cognito sign-in, a weekly report (EventBridge Scheduler → Lambda → S3 →
Lambda → SES) and an agenda parser on Bedrock. Lab 9 asks what it takes to run the
same system on Google Cloud. We move the **core** (frontend, API, database) and
leave the rest on AWS.

## Decision

| Peach on AWS | On Google Cloud | Decision | Why |
|---|---|---|---|
| S3 + CloudFront (Free plan) + WAF, static frontend | Firebase Hosting | **Replace** | Free plan, CDN + managed HTTPS; `/api/**` rewrite to Cloud Run gives one origin and no CORS (`firebase.json`). |
| Lambda + function URL, FastAPI (Mangum) | Cloud Run | **Replace** | Same Docker image runs locally and on Cloud Run; Mangum removed. Min instances 0, max 2. |
| ECR | Artifact Registry | **Replace** | Image ≈ 96 MB compressed; cleanup policy keeps 3 versions, inside 0.5 GB free. |
| Aurora Serverless v2, 0–1 ACU | Cloud SQL for PostgreSQL 17, db-f1-micro, 10 GB SSD, us-central1 | **Replace** | Keeps SQL, SQLAlchemy models and Alembic migrations unchanged. Does not pause; stopped by hand (`db_activation_policy`). |
| DynamoDB (mailer dedup state) | Firestore | **Keep on AWS** | Only used by the weekly report, which stays on AWS. |
| Cognito user pool + Google | Identity Platform | **Keep on AWS** | Sign-in stays on AWS (stretch goal). Cloud Run verifies Cognito access tokens with the public JWKS, so nothing moves. |
| EventBridge Scheduler | Cloud Scheduler | **Keep on AWS** | Weekly report stays on AWS. |
| SQS | Pub/Sub / Cloud Tasks | **Keep on AWS** | Part of the report pipeline. |
| S3 event → Lambda | Cloud Storage + Eventarc → Cloud Run | **Keep on AWS** | Part of the report pipeline. |
| SES | no Google service | **Keep on AWS** | Multicloud allowed; SES is already verified and sending. |
| Bedrock (Nova Lite) | Vertex AI (Gemini / Claude) | **Keep on AWS** | Agenda parser stays on AWS (stretch goal: compare with Gemini). |
| SSM Parameter Store / Secrets Manager | Secret Manager | **Replace** (for the API) | DB password generated by Terraform (`random_password`), stored in Secret Manager, injected as `DB_PASSWORD`. |
| CloudWatch Logs | Cloud Logging | **Replace** (for the API) | Automatic for Cloud Run stdout; 50 GiB/month free. |
| IAM roles | Service accounts + IAM roles | **Replace** | `peach-api` SA with only `roles/cloudsql.client` + `roles/secretmanager.secretAccessor` (on the one secret). No keys, no Owner/Editor, not the default compute SA. |
| WAF | Cloud Armor | **Drop** | Cloud Armor needs an external HTTPS load balancer (billed hourly). Not worth it for a student app; the API checks tokens itself. |
| Terraform `aws` provider (`infra/`) | Terraform `google` provider (`gcp/`) | **Replace** (new root) | Separate folder, separate HCP workspace `peach-gcp`: one plan can't break both clouds. |

## The three questions

**1. The database.** Options and what each does:

| Option | Latency | Bill (idle month) | Code |
|---|---|---|---|
| Cloud SQL 24/7 | ~1 ms, same region as Cloud Run, unix socket | ≈ $9.40 | No change (only how the URL is built) |
| Cloud SQL, stopped at night/outside use | Same when running; first request after a start waits for the start (minutes, manual) | ≈ $1.70 stopped + $0.0105/h running | No change |
| Firestore | Low, serverless | $0 within daily free quota | Rewrite models, migrations, services; no joins |
| Keep Aurora on AWS, call across clouds | +15–40 ms per query us-central1 ↔ us-east-1, several queries per request; AWS egress $0.09/GB | ≈ $0.30, but Aurora must be publicly reachable or behind a VPN | No change, but TLS/public endpoint and cross-cloud credentials |

**Chosen: Cloud SQL db-f1-micro, stopped when not in use** (`db_activation_policy =
"NEVER"`). Peach's data is relational (items, meetings, agendas with foreign keys,
five Alembic revisions); rewriting it for Firestore to save ~$9 is not worth it for
a course project. Cross-cloud Aurora adds latency on every query and needs a public
database. Schema: run the migrations against the empty database (the container runs
`alembic upgrade head` on start), not `pg_dump` — the AWS data is test data.

**2. E-mail.** Keep **Amazon SES** on AWS. The only sender is the weekly-report mailer
Lambda, which stays on AWS, so its credentials stay what they are now: the Lambda's
IAM role, no API key at all. If the mailer later moves to Cloud Run, it would call SES
with an IAM user key or (better) SendGrid with an API key stored in **Secret Manager**
and read by its own service account, never in the repository.

**3. What we would not move, and why.**
- **Weekly report** (Scheduler, SQS, S3 events, DynamoDB, SES): five AWS services
  wired together and working; moving it is rewriting it, and SES has no GCP twin.
- **Agenda parser** (Bedrock Nova Lite): prompts and evaluation were tuned for Nova;
  the trial credit doesn't pay for Gemini in AI Studio or Claude on Vertex.
- **Sign-in** (Cognito): moving users means a password reset for every account; the API
  can verify Cognito tokens from anywhere.
- **WAF**: dropped, see table.

## Consequences

- `backend/app/lambda_handler.py` and `mangum` are gone. The API image listens on `$PORT`.
  The AWS `lambda` image stage remains for the parser, report and migration Lambdas.
  The AWS backend workflow no longer deploys on push to main (manual only).
- Cloud SQL bills by the hour while running. Stopping it is a Terraform variable or one
  `gcloud` command (README). Storage ($1.70) is billed even when stopped.
- Peach is now multicloud: frontend + API + DB on GCP; auth, reports, parser, e-mail on AWS.
  Cognito callback URLs must include the Firebase origin before sign-in works there.
- **Not deployed.** The GCP side is checked locally instead: `terraform validate` for `gcp/`, and the API image run with Docker Compose. The deploy steps in the README are the procedure for a real project.
